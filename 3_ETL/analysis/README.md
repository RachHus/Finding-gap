# 3_ETL/analysis — 변수 선택 근거 (파이프라인 단계 아님)

여기 있는 파일은 **다시 돌리는 코드가 아니라, 한 번 내린 판단을 검산한 기록**이다.
`run_pipeline.py` 가 부르지 않고, 서비스도 읽지 않는다. 지워도 화면은 그대로다.
남겨 두는 이유는 "왜 환경변수를 이 조합으로 골랐는가"를 나중에 물었을 때
숫자로 답할 수 있어야 하기 때문이다.

## 무엇을 재는가

여러 환경변수를 한 모형에 같이 넣을 때, 서로 너무 닮은 변수가 섞여 있으면 계수가 요동쳐
어느 쪽이 효과를 낸 건지 갈라내지 못한다. 이 겹침의 정도를 재는 값이 VIF(분산팽창인자)다.
값이 클수록 "이 변수는 다른 변수들로 거의 설명된다"는 뜻이다.

`vif_all_variables.csv` 를 보면 왜 정리가 필요했는지 바로 보인다. 후보 21개를 다 넣으면
연평균기온 계열(bio05·bio06·bio07)의 VIF 가 10억 단위로 튄다 — 셋이 사실상 같은 정보다.
반대로 ndvi 는 1.23 으로, 다른 무엇으로도 대신할 수 없는 정보를 갖고 있다.

## 파일

| 파일 | 내용 |
|------|------|
| `vif_all_variables.csv` | 후보 21개를 그대로 넣었을 때의 VIF — 출발점 |
| `vif_detailed_analysis.R` | 검산 스크립트. 상관·결측·표본 대표성을 같이 본다 |
| `vif_comparison_reported.csv` | 보고서에 실은 값(`reported_vif`)과 다시 계산한 값(`recalc_vif`)의 대조. 최대 차이 0.30 으로 재현됨 |
| `vif_final_selected.csv` | 남긴 6개의 VIF — 전부 1.7 이하 |
| `final_vars_biodef.csv` | 그 6개의 이름·설명·축 분류 |

## 주의: 서비스 모형이 쓰는 변수는 이것과 다르다

두 목록을 같은 것으로 착각하기 쉬운데, 서로 다른 판단이다.

| | 변수 | 어디에 |
|---|---|---|
| 이 폴더(보고용) | bio03 · bio05 · bio07 · bio12 · bio14 · ndvi | CSV 로만 존재 |
| 서비스 모형 | dem · ndvi · bio01 · bio18 · bio03 · bio14 | `3_ETL/R/model_config.R:19` 의 `V` |

서비스 모형은 종마다 점유 셀 수에 따라 `V` 앞에서부터 3~6개를 잘라 쓴다(같은 파일의
`TIERS`·`nvar_for`). 그래서 "중첩 순서"가 중요해 순서 자체가 설계값이고, VIF 상한도
4.63 으로, 전부 1.72 아래인 이 폴더의 조합보다 느슨하다. 모형 변수를 바꾸려면 `model_config.R`
을 고쳐야 하며, 그 파일 머리말에 적힌 대로 전 종 재적합(약 10시간)이 따라온다.
